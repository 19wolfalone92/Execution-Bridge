# Chat round-trip experiment
The supported immediate path is owner-mediated ordinary ChatGPT text/file exchange (no server, no Work). Chat generates EB1:uuid:issued_ms:expires_ms:32hexnonce. The user explicitly copies it to the non-exported ChallengeActivity, presses the battery read button, reviews the response and manually attaches it to the original chat. No commands other than a battery reading exist. TTL <=30 minutes, local consumption recorded before exposing a result, exact correlation, no attestation. A fresh response proves correlation of a user-mediated exchange, not remote automation or hardware authenticity. Do not publish any response in GitHub. No direct app link to ChatGPT is assumed.

CI builds a separate test package io.executionbridge.android.challenge (Execution Bridge Test), so a new debug signing certificate does not require uninstalling the existing io.executionbridge.android app. This test package is not an upgrade; app data is separate. Default source application ID is unchanged. No update of Williams Bot.

Custom MCP connection: plan/surface limits (https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt). Sites creation requires Work or desktop Codex (https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites). Existing private skills plugin is not a server. Android Sharesheet availability in ChatGPT is unverified; SAF file attachment is the fallback. Do not turn email, public GitHub, private GitHub or cloud storage into an unattended command queue or bypass platform controls.
